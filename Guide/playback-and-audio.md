# MuseScore — Playback & Audio

> **What this file is.** Deep pass (2026-11-08) over `src\playback` (app orchestration), `src\engraving\playback` (score -> MPE events), and the Muse audio framework `muse\framework\audio` (`main\` proxy side, `engine\` real engine, `driver\`, `common\`). Source-verified; cites are `path:line` relative to `C:\Dev\+MuseScore+`. VST / MuseSampler / MIDI / MPE internals live in `midi-vst-musesampler.md` (not duplicated here). **If this contradicts the live source, the source wins.** Start at `00-core.md`.

## 0. 60-second orientation

- ⭐ **Pipeline:** `Score` change -> `PlaybackModel` (engraving) renders `mpe::PlaybackEvent`s per instrument track -> `NotationPlayback` exposes them -> `PlaybackController` (app) creates audio tracks via `muse::audio::IPlayback` (RPC to engine) -> engine `AudioContext` -> per-track `TrackChain` (source -> fx -> control -> signal) -> context `Mixer` -> master chain -> global `MixerNode` -> `AudioEngine::process()` called from the **driver callback**.
- ⭐ **There is a hard RPC boundary** between `audio\main` (main/GUI thread, proxies) and `audio\engine` (worker/driver threads). `IPlayback`/`IPlayer` calls never touch the engine directly; they send `rpc::Msg`s (`muse\framework\audio\common\rpc\irpcchannel.h`).
- ⭐ **One audio context per IoC context (window).** `AudioEngine` is global; each window gets an `engine::AudioContext` (tracks, mixer, player, master chain) keyed by `ctxId` (`audioengine.cpp:89-113`).
- Layers / files that matter most:
  1. `src\engraving\playback\playbackmodel.*`, `playbackeventsrenderer.*`, `playbackcontext.*`, `renderers\`, `metaparsers\`.
  2. `src\playback\internal\playbackcontroller.*` (2187-line `.cpp`), `soundprofilesrepository.*`, `playbackconfiguration.*`, `onlinesoundscontroller.*`, `drumsetloader.*`.
  3. `muse\framework\audio\main\internal\{playback,player,startaudiocontroller,audiodrivercontroller}.*`.
  4. `muse\framework\audio\engine\internal\{audioengine,audiocontext,contextplayer,mixer}.*`, `nodes\*`, `synthesizers\fluidsynth\*`, `enginerpccontroller.*`.
- `muse\framework\audio\README.md` is one line ("audio engine - drivers, worker, sources, mixer, chains, synthesizers"); no further in-repo doc. ADR `muse\docs\adr\00103` covers automation (see §8).

## 2. Threading model and the main <-> engine boundary

### 2.1 Work modes
`workmode::Mode` (`common\workmode.h:29-42`): `WorkerMode_NOT_SUPPORTED=1`, `DriverMode=2` (everything in the driver thread; web), `HybridMode=3` (RPC operations on a worker thread, audio processing directly in the driver callback). Default comes from `MUSE_MODULE_AUDIO_WORKMODE` (`workmode.cpp:56-59`): **3** for APP / APP-PORTABLE (`SetupConfigure.cmake:94,100`, default `MuseDeclareOptions.cmake:59`), **2** for APP-WEB (`SetupConfigure.cmake:136`). Overridable by setting `audio/dev/workmode` (values 1..3; 1 is coerced to Hybrid with a warning, `workmode.cpp:39-54`); `setMode` needs a restart.

### 2.2 The threads (Hybrid mode, desktop)
| Thread | Who | What runs |
|---|---|---|
| main/GUI | everything in `audio\main`, `PlaybackController` | RPC `process()` ticked every 1 ms (`audiomodule.cpp:118-124`, `Ticker::Mode::Repeat`) |
| `audio_engine` worker | `GeneralAudioWorker` (`engine\platform\general\generalaudioworker.cpp:54-128`), High priority | `th_setupEngine` once, then every **16 ms**: `async::processMessages` + `m_rpcChannel->process()` (`startaudiocontroller.cpp:93-108`). This is the "engine/RPC thread": all `ContextPlayer`/`AudioContext` mutations, soundfont loading, track creation. |
| driver (audio callback) | platform driver | `StartAudioController` lambda -> `EngineController::process` -> `AudioEngine::process` -> mixer render. The "PROC" thread. |
| `audio_rt` pool | `AudioTaskScheduler` (`common\audiotaskscheduler.h:37-93`) | Optional per-track parallel render in `Mixer`; size = `hardware_concurrency/2` (or workgroup hint), re-created when the driver workgroup changes |

In `DriverMode`, `th_setupEngine` is run lazily inside the first driver callback and RPC is processed there too (`startaudiocontroller.cpp:189-196`).

### 2.3 RPC channel
`IRpcChannel` (`irpcchannel.h:394-429`): `send(Msg, onResponse)`, `onRequest/onNotification(ctxId, MsgCode, handler)`, plus **streams** (`addSendStream` / `addReceiveStream`) that bridge an `async::Channel<...>` across the boundary (`RpcStream`, `irpcchannel.h:345-377`). `Msg` = `{callId, ctxId, code, type, ByteArray data}`; `MsgType`: Notification/Request/Response/ResponseDelayed/Stream. `ctxId 0` = global, `>0` = window (`irpcchannel.h:278-284`). Payloads are serialized with `RpcPacker`. `MsgCode` enum (`irpcchannel.h:52-149`) is the full command vocabulary: Init/Deinit (`EngineInit`, `EngineRunning`, `EngineDeinit`, `ContextInit/Deinit`), `SetOutputSpec`, resources, tracks, params, `PrepareToPlay/Play/Seek/Stop/Pause/Resume/SetDuration/SetLoop/ResetLoop`, `SaveSoundTrack`, soundfonts, `TransportEventReceived`, and stream ids starting at `FirstStream=100`.

`GeneralRpcChannel` (`generalrpcchannel.cpp`): a two-port `RpcQueue<Msg>`; **port1 = main thread, port2 = engine RPC thread** (`generalrpcchannel.h:75-77`). The calling side is decided by a `thread_local s_isMainThread` set in `setupOnMain` (`:38,46-54`); each side keeps its own `RpcData` (handlers, pending responses, streams). `receive()` (`:108-155`) dispatches: Stream -> `onStreams`, Request -> handler then auto-`send(resp)` unless `ResponseDelayed`, Response -> pending callback, Notification -> `onNotifications`.

⭐ **Request handlers are keyed `(ctxId, code)` and only ONE handler per key** (`std::map<MsgKey,...>`), assignment overwrites (`:157-173`).

### 2.4 Engine-side operation gating (`IExecOperation`)
Every request on the engine thread runs through `AudioEngine::execOperation(type, func)` (`audioengine.cpp:170-196`), `OperationType` = `NoOperation / QuickOperation / LongOperation` (`engine\internal\iexecoperation.h:31-38`). Mechanism:
1. spin-wait (`sleep 1ms`) while `m_processing` (a render is in flight);
2. set `m_operationType`; for Quick, lock `m_quickOperationWaitMutex`;
3. run `func`; restore.
`AudioEngine::process` (`:204-241`): clears the buffer; if not inited returns silence; `NoOperation` -> render; `QuickOperation` -> blocks on the mutex then renders; `LongOperation` -> returns **silence** (0 samples) for the duration. `EngineRpcController::onRequest` wraps each handler (`enginerpccontroller.cpp:869-893`); `onLongRequest`/`onQuickRequest` pick the type (`:859-867`): SetOutputSpec, LoadSoundFonts, AddSoundFont*, EngineConfigChanged, ContextInit, AddTrack* are Long; resource queries, ContextDeinit are Quick. Incoming playback-data streams are also exec'd as Quick (`:199-216`).

`ONLY_ON_OPERATION_EXEC` marks ContextPlayer methods that must run inside an operation (`contextplayer.cpp:176,190,...`).

### 2.5 Sanitizer macros are compiled OUT
`audiosanitizer.h:53-79`: `AUDIO_SANITIZER_ENABLED` is defined then **unconditionally `#undef`'d at line 61** (the guarding `#if` is commented out), so `ONLY_AUDIO_ENGINE_THREAD / ONLY_AUDIO_MAIN_THREAD / ...` expand to nothing. Treat them as documentation of intended thread ownership, not enforcement. `AUDIO_SANITIZER_OPERATION_ENABLED` stays on (asserts `isOperationExec`).

## 3. Startup / shutdown sequence

1. `AudioModule::onInit` (`audiomodule.cpp:110-140`): `configuration->init()`; `rpc->setupOnMain()`; 1 ms rpc ticker; `StartAudioController::init()`; `startAudioProcessing(mode)`.
2. `StartAudioController::init` (`startaudiocontroller.cpp:82-110`): registers a handler for global `EngineRunning` notification; `workmode::load()`; in Hybrid creates `GeneralAudioWorker` whose first tick runs `th_setupEngine` (`:65-78`: sets thread name `audio_engine`, `AudioSanitizer::setupEngineThread`, `rpc->setupOnEngine()`, `new EngineController`, `onStartRunning()`), then sets interval 16 ms.
3. `EngineController` ctor registers `EngineInit`/`EngineDeinit` requests (`enginecontroller.cpp:44-64`). `onStartRunning` creates `EngineRpcController` (registers all other handlers) and sends `EngineRunning` (`:66-82`).
4. Main receives `EngineRunning`: `soundFontController()->loadSoundFonts()` (scans `*.sf2/*.sf3` in `soundFontDirectories()`, sends `LoadSoundFonts`, `generalsoundfontcontroller.cpp:34-72`) and sets `m_isEngineRunning` (`startaudiocontroller.cpp:84-88`).
5. `startAudioProcessing` (`:122-241`): builds `IAudioDriver::Spec` from config (`audioOutputDeviceId`, `desiredOutputSpec`), installs the callback (below), **opens the driver only in `RunMode::GuiApp`** (other modes just use the requested spec, `:215-222`), then once the engine is running sends `EngineInit(activeSpec.output, AudioEngineConfig)`; its response sets `isAudioStarted` (`:225-240`).
6. `EngineController::init` -> `configuration()->setConfig`, `synthResolver()->init(defaultInputParams, spec)`, `audioEngine()->init(spec)` (creates global `MixerNode`, sets `NoOperation`), `transportEventsDispatcher()->init()` (`enginecontroller.cpp:84-98`).
7. Per window: `Playback::init()` (`audio\main\internal\playback.cpp:49-160`) subscribes notifications (TrackAdded/Removed, Source/Fx/Control/AuxSends params changed), and **waits for `isAudioStarted`** before sending `ContextInit(ctxId)`; the response resolves the promise and sets `isInited`. Engine side `ContextInit` -> `audioEngine()->addAudioContext` and registers ~40 per-ctx request handlers (`enginerpccontroller.cpp:133-806`).
8. Shutdown `stopAudioProcessing` (`:243-289`): disconnect engine-running waiter, send `EngineDeinit`, pump `rpc->process()` up to 100 x 10 ms, close driver, stop worker. (Note the check `attempt >= attemptsLimit` logs an error even when the last attempt succeeded: loop exits via `break` before, so it only fires on real timeout or exactly at limit.)

### 3.1 The driver callback (the render loop)
`startaudiocontroller.cpp:137-211`. Per call: zero the buffer; compare `byteCount/4` (driver samples) with `m_requiredSamplesTotal = samplesPerChannel*channels` of the active spec. If the driver asks for fewer samples than the engine block, an `AlignmentBuffer` (capacity = 2 blocks, `common\alignmentbuffer.h`) is used: serve from it when enough data is buffered, else render one full engine block into a `thread_local` temp buffer, write it to the ring and read what the driver needs. Rendering = `m_engineController->process(procDest, samplesPerChannel)` -> `AudioEngine::process` (Hybrid) or, in DriverMode, `rpc->process()` first. Optional `measureInputLag` scans for the first non-zero sample.

The active spec can change at runtime (`activeSpecChanged` updates `m_requiredSamplesTotal`), and `AudioDriverController::updateOutputSpec` sends `SetOutputSpec` to the engine (`audiodrivercontroller.cpp:351-359`), which calls `AudioEngine::setOutputSpec` -> `MixerNode::setOutputSpec` (propagates to all nodes) (`audioengine.cpp:135-158`).

### 3.2 Drivers
`IAudioDriver` (`audio\iaudiodriver.h:37-71`): `init/open(Spec*, activeSpec*)/close`, `Spec{deviceId, OutputSpec, Callback(uint8_t*, int len)}`, device/buffer-size/sample-rate lists, `getAudioWorkGroup()` (macOS thread workgroup), change notifications. Factory (`audiodriverfactory.cpp:60-158`): Windows `WASAPI` (shared mode, event callback, own audio thread: `wasapiaudiodriver.cpp:420,458-460`) and `ASIO` if `MUSE_MODULE_AUDIO_ASIO`; Linux `ALSA`, `PipeWire` (`MUSE_MODULE_AUDIO_PIPEWIRE`; env `MUSESCORE_FORCE_ALSA` forces ALSA), JACK replaces everything when `MUSE_MODULE_AUDIO_JACK`; macOS `CoreAudio`/`CoreAudioDirect`; wasm `WASM`. `AudioDriverController` (`audiodrivercontroller.cpp`) owns the active driver: `open` falls back to default device then default driver (`:150-180, 291-322`), `reopenWithSpec` restores the old spec on failure (`:324-349`), `handleOutputDeviceChange` reopens on device-list changes and retries later if it fails (`:246-289`), `changeBufferSize/changeSampleRate` reopen + `SetOutputSpec`. Defaults: 44100 Hz, buffer 1024 (`audioconfiguration.cpp:40-41`), min buffer 256 (Win)/128 (else), max 4096 (`audiotypes.h:83-89`); settings keys `audio/io/{audioDriver,outputDevice,bufferSize,sampleRate}` (`audioconfiguration.cpp:44-48`).

## 4. Main-side API: `Playback` and `Player`

- `Playback` (`audio\main\internal\playback.cpp`) implements `IPlayback`; every method is "build `Msg`, `channel()->send`". Returns use `async::Promise` resolved from the response handler (`PromiseType::AsyncByBody`). Tracks: `addTrack(name, mpe::PlaybackData, TrackParams)` first **creates two send-streams** for `playbackData.mainStream` and `offStream` (`:399-400`) and ships the stream ids with the request; the engine side creates matching receive-streams (`enginerpccontroller.cpp:215-216`). From then on, the app just `send()`s on those `mpe` channels and the events cross the RPC boundary. `addTrack(name, io::IODevice*, ...)` (sound-file tracks) sends the raw pointer as `uint64_t` (`:369`) and is `NOT_SUPPORTED` on web; engine `AudioContext::addTrack(IODevice*)` is not implemented (`audiocontext.cpp:165-166`).
- Per-track extra streams are requested lazily (`signalChanges`, `automatedControlParamsChanges`, `inputProcessingProgress`) and tracked in `m_trackStreams` so they are dropped on `TrackRemoved` (`playback.cpp:190-207`).
- `Playback::player()` lazily creates a `Player` (`:219-232`), asserting `isInited`. `Player` (`player.cpp`) mirrors engine state: on `init` it requests `GetPlaybackStatus` / `GetPlaybackPosition`, each returning a stream id; it caches `m_playbackStatus`/`m_playbackPosition` (`:39-94`). ⭐ `Player::seek` is **skipped if `m_playbackPosition == newPosition`** (`:135-137`) — position is the (async-lagging) cached value.
- Master track = `MASTER_TRACK_ID = 0`; master params use the same messages with trackId 0 (`playback.cpp:543-576`).
- Sound-track export: `saveSoundTrack(format, dstDevice)` (`:703-725`) sends the device pointer; engine renders offline (§5.7).

## 5. Engine internals

### 5.1 Node graph primitives
`AudioNode<Tag>` (`engine\internal\nodes\audionode.h`): single `m_input`, `connect(other)` means "other.input = this" (`:271-282`), `process()` first pulls `m_input->process(buffer)` then (unless bypassed) `doSelfProcess` (`:340-355`); `setOutputSpec/setMode/setEnabled` propagate **toward the input**. `ChainNode::rebuild` (`chainnode.h:53-61`) links nodes in vector order so that chain input = first node. `MixerNode` has many inputs, renders each into a scratch buffer and sums (`nodes\mixernode.cpp:55-85`).

### 5.2 Context graph
`AudioContext` ctor/init (`audiocontext.cpp:41-86`): `ContextPlayer m_player`, `PlayheadNode(m_player)`, per-context `Mixer`, master `TrackChain`. Graph (pull order, root = `AudioContext::doSelfProcess` -> `m_playheadNode->process`, `:969-973`):
```
AudioContext -> PlayheadNode(forward time) <- master TrackChain[ signal <- control(Automation) <- (fx: none yet) <- source=Mixer ]
Mixer <- per-track TrackChain[ signal <- AutomationControlNode <- FxChain <- source (EventAudioNode) ]
```
Audible order inside a track: **synth -> FX chain -> volume/pan -> peak meter** (`trackchain.cpp:35-53` doAdd order signal, control, fx, source; the first-added is nearest the output). `PlayheadNode::doSelfProcess` advances the player by `samplesPerChannel` *after* the chain rendered (`playheadnode.cpp:35-38`). `AudioEngine::addAudioContext` connects each context to the global `MixerNode` (`audioengine.cpp:110`).

### 5.3 Mixer (per context)
`Mixer::process` (`mixer.cpp:142-172`): render all track chains (`processTrackChannels`), clear aux buffers, for each processed non-silent track add into the output and into aux buffers weighted by `AuxSendParams.signalAmount`, then `processAuxChannels` (aux chains such as Reverb; an aux is processed if it received signal or is not yet silent, so reverb tails ring out, `:311-330`). Aux tracks are indexed by creation order (`writeTrackToAuxBuffers` uses aux index = `auxSends` index, `:283-309`). Parallelism: `useMultithreading()` (`:228-251`) requires `MUSE_THREADS_SUPPORT`, not `PlayingOffline`, >= 2 non-muted tracks, and in Idle >= 2 `tracksToProcessWhenIdle`; tasks go to `IAudioTaskScheduler::submitRealtimeTasksAndWait`.

⭐ **Idle filtering:** when the context mode is `Idle` and `m_tracksToProcessWhenIdle` is non-empty, only those tracks render (`mixer.cpp:191,199-216`). Tracks enter this set when (a) their offStream receives events (`audiocontext.cpp:187-198`, previous+current track) or (b) their `FxChain` reports `shouldProcessDuringSilence` (`:511-521`). This is how note-preview (editing) sound works while stopped without rendering all tracks.

### 5.4 ContextPlayer (transport)
`engine\internal\contextplayer.cpp`. State: `PlaybackStatus {Stopped, Paused, Running}`, `m_isActive` (Running and countdown finished), current `TimePosition` (sample-accurate), loop range, duration, countdown.
- `forward(delta)` on the **proc thread** (`:77-94`): only when Running; `proc_onTimeChanged` (`:96-128`) handles count-down (subtract; emit `CountDownEnded`), loop (if `loopStart < loopEnd && t >= loopEnd`: emit `LoopEnded`, wrap with overshoot), duration (`t >= duration`: emit `PlaybackEnded`, clamp). Events are forwarded to the engine thread via `m_timeEvent` channel and handled in `onTimeEvent` (`:135-158`): CountDownEnded -> activate; LoopEnded -> `seekAllTracks`; PlaybackEnded -> `pause()`.
- `onStatusChanged` (`:62-75`): Running (and no countdown) -> `m_isActive=true`; else inactive + `flushAllTracks()`. `AudioContext::init` maps `isActiveChanged` -> `setMode(Playing/Idle)` (`audiocontext.cpp:81-83`) which flows through every node (`onModeChanged`, `:113-122`) into synths (`EventAudioNode::onModeChanged` -> `synth->setMode` + `flushSound`).
- `play(delay)`, `resume(delay)` (re-seeks), `stop()` (status Stopped + seek 0), `pause()`, `seek(pos, flushSound)` (sets position, `seekAllTracks`) (`:173-252`). `prepareToPlay` (`:160-171, 353-398`): calls `source->prepareToPlay()` on every source (requires Idle mode, asserted) and resolves a promise when all `readyToPlay()` (MuseSampler/VST may need time).
- ⭐ Pause at the end: playhead hits `duration` -> engine `pause()`. The app additionally calls `doStop()` when `pos + 1ms >= totalPlayTime` (`playbackcontroller.cpp:1860-1863`).

### 5.5 Event sources: `EventAudioNode` + sequencers
`AudioFactory::makeEventSource` (`audiofactory.cpp:72-80`) builds an `EventAudioNode(trackId, PlaybackData, onOffStream)`, sets output spec, `applyInputParams(params)`. `applyInputParams` (`eventaudionode.cpp:121-165`) asks `SynthResolver::resolveSynth(trackId, params, spec, setupData)` (`synthresolver.cpp:45-72`: lookup resolver by `AudioSourceType`, check `hasCompatibleResources(setupData)`); if that fails it **falls back to `makeDefaultSynth`** (Fluid); it preserves the synth's mode/position across swaps (`SynthCtx`), wires `paramsChanged`, `setup(playbackData)`. `doSelfProcess` = `m_synth->process(buffer, n)` (`:76-84`).

Resolvers: `Fluid` registered in `EngineGlobalSetup::resolveImports` (`enginesetup.cpp:70-74`, plus `MuseFx` for fx); `Vsti` by `vstmodule.cpp:74` (+`VstFx` `:79`); `MuseSampler` by `musesamplermodule.cpp:67`. See `midi-vst-musesampler.md`.

`AbstractEventSequencer<Types...>` (`engine\internal\abstracteventsequencer.h`) is the shared time-ordered event feeder; `FluidSequencer` (`<midi::Event>`), `VstSequencer`, `MuseSamplerSequencer` derive from it. Key mechanics:
- `load(PlaybackData)` subscribes to `mainStream` (events + dynamics curves) and `offStream` (preview events, with a `flush` flag) (`:57-84`). Main-stream updates are **lazy**: stored and applied only when the sequencer is active (or `updateMainStreamWhenInactive`), via `m_shouldUpdateMainStreamEvents` (`:63-72, 91-97, 118-129`).
- `movePlaybackForward(nextMsecs)` (`:167-197`): inactive -> only drains the off stream (own `m_offstreamPosition` clock, events erased once played); active -> advances `m_playbackPosition` and returns the events in `[prev, now]` keyed by timestamp. ⭐ Timestamps in "msecs_t" are actually **microseconds** (comment in `fluidsynth.cpp:399-401`; `samplesToMsecs` multiplies by 1,000,000, `abstractsynthesizer.cpp:119-122`).

### 5.6 Fluid synth (built-in "MuseScore Basic")
`FluidSynth::init` (`fluidsynth.cpp:79-154`): gain 4.8, 1 stereo pair, 16 MIDI channels, **polyphony 512**, dynamic sample loading, thread-safe API off, chorus/reverb off (reverb is an aux FX instead), optional IIR low-pass (from `AudioEngineConfig.useSoundFontLowPassFilter`). Rendering (`process`, `:409-445`): apply pending flush; ask the sequencer for events up to now; render **sample-accurately between event timestamps** (`fluid_synth_write_float` per slice, `:447-468`), applying each `midi::Event` (`handleEvent`, `:221-264`; NoteOn velocity 7-bit, tuning per note via `fluid_synth_tune_notes`, optional echo to a connected MIDI-out port with staff->channel mapping). `FluidSequencer::addNoteEvent` (`fluidsequencer.cpp:177-241`) converts `mpe::NoteEvent` -> NoteOn/NoteOff (+CC11 expression for off-stream with SND), pitch curves -> pitch-bend (`addPitchCurve`), sustain/sostenuto pedal articulations -> CC64/66; `expressionLevel` maps dynamic level -> CC 16..127 (`:428-454`); single-note-dynamics instruments get per-layer expression CC every 30 ms from the dynamics curve (`addDynamicEvents`, `:142-175`). Soundfonts come from `SoundFontRepository` (loaded over RPC; `FluidResolver::refresh` builds one resource per soundfont + one per bank/program preset, `fluidresolver.cpp:102-144`). Track creation for a Fluid track **waits until its soundfont is loaded** (pending queue, `enginerpccontroller.cpp:229-270`).

### 5.7 FX, control, signal, export
- `FxChain` (`nodes\fxchain.cpp`): `FxNode`s built from `IFxResolver` by `AudioFxChain` (map order -> processor); bypass follows `AudioFxParams.active`; `shouldProcessDuringSilence` aggregates (reverb tails). Built-in `MuseFx` currently resolves **only the reverb** (`musefxresolver.cpp:33-42`); VST FX via `VstFxResolver`.
- `AutomationControlNode` (ADR 00103) replaced `ControlNode` in the graph: volume/pan are `AutomatableValue<T>` = fixed value **or** an `AutomationEnvelope` keyed by seconds (`common\automatablevalue.h:36-70`); gains are recomputed from the playhead position when automated and smoothed per sample (`automationcontrolnode.cpp:74-139`), and a throttled `automatedControlParamsChanges` stream feeds the UI. Mute = `setEnabled(false)`. `ControlNode` (non-automated) still exists.
- `SignalNode` computes per-channel peaks, `isSilent`, dBFS updates with a 2.5 dB hysteresis (`signalnode.cpp:28-29,77-94`); the mixer skips silent chains.
- Export: `AudioContext::saveSoundTrack` (`audiocontext.cpp:777-812`, `MUSE_MODULE_AUDIO_EXPORT`): stop+seek 0 in a LongOperation, temporarily disable lazy online processing, wait for online sounds to finish processing, then `doSaveSoundTrack` (`:909-953`) renders offline with `SoundTrackWriter` inside a LongOperation with `ProcessMode::PlayingOffline` (so the driver renders silence meanwhile; comment explains a data race otherwise). Encoders: wav/mp3/ogg/flac/aac under `engine\internal\export\`.

## 6. Score -> events (`src\engraving\playback`)

### 6.1 Data types (`muse\framework\mpe`)
`mpe::PlaybackData { originEvents (PlaybackEventsMap), setupData (PlaybackSetupData), dynamics (DynamicAutomationLayers), mainStream, offStream }` (`mpe\events.h:351-370`). `PlaybackEvent = variant<monostate, NoteEvent, TextArticulationEvent, SoundPresetChangeEvent, SyllableEvent, ControllerChangeEvent>` (`:335-340`); `PlaybackEventsMap = SharedMap<timestamp_t(us), PlaybackEventList>` (`:343`). `mainStream` = `Channel<PlaybackEventsMap, DynamicAutomationLayers>` (score playback); `offStream` = `Channel<PlaybackEventsMap, bool flush>` (one-shot preview/metronome/count-in events) (`:348-349`). `PlaybackSetupData{id, subCategories, category, supportsSingleNoteDynamics, scoreId, musicXmlSoundId}` identifies "what instrument sound this is" and is the key used to pick a resource from a sound profile (`mpe\playbacksetupdata.h:31-185`). NoteEvent/ArticulationMap/pitch-level math: see `midi-vst-musesampler.md`.

### 6.2 `PlaybackModel` (`playbackmodel.h/.cpp`, owned by `NotationPlayback::m_playbackModel`, `notationplayback.cpp:59`)

### 6.3 Rendering pipeline per chord

`PlaybackContext` (`playbackcontext.h/.cpp`) is the per-track timeline of non-note state keyed by tick: `appliableDynamicLevel` (interpolates the *dynamics automation curve*, default NATURAL, `:87-108`), playing techniques, sound presets and text articulations from **SoundFlags** (`soundFlagPlayable`: flag->play() and has presets or technique; per-track acceptance via `applyToAllStaves`, `:52-59, 404-463`), lyric syllables, and `dynamicLevelLayers` -> `DynamicAutomationLayers` converted to microsecond timestamps with the expanded repeat timeline (`:241-282`).

## Non-obvious gotchas

1. ⭐ **Never assume engine state is synchronous.** `IPlayer` position/status are cached mirrors updated by streams; every setter is a message. `Player::seek` is dropped when it equals the cached position (`player.cpp:135`).
2. ⭐ **Events reach the engine only when "send on score change" is enabled** for that track (or via `sendEventsForChangedTracks`). Editing while stopped is deliberately *not* streamed; `play()` flushes. If playback seems stale after an edit, check `m_sendEventsOnScoreChangeMap` / `m_changedTrackIdSet`.
3. ⭐ **Timestamps are microseconds** even where the type is named `msecs_t`/`timestamp_t` (`fluidsynth.cpp:399-401`).
4. Raw tick != played tick (repeats). Use `playPositionTickByRawTick` / `playedTickToSec` / `secToTick` (`notationplayback.cpp:292-334`); `secToTick` converts back through `expandedRepeatList().utick2tick`.
5. **Long operations silence the output** (`LongOperation` -> `AudioEngine::process` returns without rendering). Adding tracks, soundfont loads, context init and export all do this.
6. Fluid track creation is deferred until its soundfont is loaded (pending queue); a missing soundfont name never resolves -> `AddTrack` response never arrives (the app's `m_loadingTrackCount` then never reaches 0 and `isPlayAllowed()` stays false). HYPOTHESIS for the never-resolves case: traced the pending logic (`enginerpccontroller.cpp:229-270`) but not the branch where the soundfont is absent and nothing is loading (lines ~270-282 not read).
7. `SynthResolver::resolveSynth` failure silently falls back to the default Fluid synth (`eventaudionode.cpp:137-143`) — a broken VST/MuseSampler track can "work" with the wrong sound.
8. The thread-ownership asserts are compiled out (`audiosanitizer.h:61`); do not rely on them to catch cross-thread calls.
9. Engine objects are created on the main thread and registered in the global IoC; the IoC is not thread-safe (`enginesetup.cpp:49-53`), so engine-thread code resolving `GlobalInject` services is a known design weak spot (comment in `enginecontroller.cpp:88-93`).
10. HYPOTHESIS (not reproduced): in Hybrid mode `m_engineController` is assigned on the worker thread (`th_setupEngine`) but dereferenced without a null check in the driver callback (`startaudiocontroller.cpp:187`); the driver is opened right after the worker is launched (`:217`), so a callback firing before `th_setupEngine` finishes would crash. Driver start latency probably hides it.
11. `Mixer::addTrack` lacks the `ONLY_AUDIO_ENGINE_THREAD` marker `addAuxTrack` has (`mixer.cpp:58 vs 77`) — harmless (macros are empty) but shows aux/track paths are not symmetric.
12. Online-sound (MuseSampler cloud) tracks force streaming of events on every score change and block play with an error dialog while processing (`playbackcontroller.cpp:700-703`).
13. Export (`saveSoundTrack`) disables lazy online processing temporarily and requires all online tracks to finish; failing leaves `Ret::Code::Cancel`.
14. Web build (`APP-WEB`): `DriverMode`, no threads (`MUSE_THREADS_SUPPORT OFF` on wasm), audio export/plugins/automation modules OFF (`SetupConfigure.cmake:115-154`); `IODevice` tracks unsupported.
